# Семестр

Курсовая работа по дисциплине «Веб-программирование II» для очной формы обучения.
Тема: **«Приложение для планирования учебного семестра»**.

Репозиторий проекта: [arniiii/web](https://github.com/arniiii/web).

Студент ведёт свои дисциплины, добавляет задания и дедлайны, отмечает выполнение и видит прогресс. Данные хранятся в PostgreSQL; после перезапуска приложения они сохраняются.

## Возможности

- Регистрация, вход по JWT, выход и редактирование профиля.
- Дисциплины: создание, список, карточка, редактирование и удаление.
- Задания: создание, список, карточка, редактирование, удаление и смена статуса.
- Поиск по названию, фильтры по дисциплине, статусу, приоритету и срокам; сортировка.
- Обзор ближайших дедлайнов, просроченные задания и прогресс.
- Адаптивный интерфейс, управляемые формы, загрузчики и сообщения об ошибках.
- Защита личных данных на сервере, в том числе при ручной подстановке ID.

## Быстрый локальный запуск без Docker

Нужны Linux/macOS, **Node.js 22.12+ (рекомендуется 24)**, npm и **Python 3.12+** с модулем `venv`. В Ubuntu при отсутствии `venv` установите пакет `python3-venv`. Все команды ниже выполняются из корня проекта.

```bash
npm ci
npm run setup
```

Команда настройки создаёт `backend/.venv`, устанавливает зафиксированные Python-зависимости и создаёт `backend/.env` со случайным JWT-ключом. Существующий `.env` не перезаписывается. Секреты и данные БД исключены из Git.

**Терминал 1 — база данных:**

```bash
npm run dev:db
```

Это настоящий локальный PostgreSQL, запущенный через `embedded-postgres`, а не SQLite или имитация БД. Он слушает `127.0.0.1:55432` и сохраняет данные в `.local/postgres`. Первый запуск требует места для скачанных бинарных файлов. PostgreSQL отказывается запускаться от root; используйте обычного пользователя. Для окружения без поддерживаемых бинарных файлов используйте собственный PostgreSQL или Docker.

**Терминал 2 — схема, демо и API:**

```bash
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head
cd backend
.venv/bin/python -m app.seed
cd ..
npm run dev:api
```

**Терминал 3 — интерфейс:**

```bash
npm run dev:web
```

Откройте [приложение](http://127.0.0.1:5173). Документация API: [Swagger UI](http://127.0.0.1:8000/docs). Проверка подключения к БД: [health](http://127.0.0.1:8000/api/health).

Демо-аккаунт: `demo@semester.app`, пароль `Semester2026!`. Это публичные учебные данные. Повторный запуск `app.seed` не меняет существующий аккаунт. Новый пользователь начинает с пустого плана.

Для остановки используйте `Ctrl+C` в каждом терминале. Повторный запуск использует ту же БД. Не удаляйте `.local/postgres`, если нужны сохранённые данные.

## Собственный PostgreSQL

Пример настроек находится в `backend/.env.example`. Создайте две базы: `semester` и `semester_test`, укажите их URL в `backend/.env`. Для поиска кириллицы используется collation `und-x-icu`; PostgreSQL должен быть собран с ICU, как официальный образ PostgreSQL в Compose.

`frontend/.env.example` описывает адрес API. При локальном запуске Vite проксирует `/api` на порт 8000. Если сервер работает на другом адресе, создайте `frontend/.env` и измените `API_PROXY_TARGET`. При прямом доступе к API добавьте адрес клиента в `CORS_ORIGINS` сервера.

## Docker Compose

Используйте этот вариант **вместо** локальных процессов на тех же портах. Нужен доступ к Docker daemon.

```bash
python3 scripts/setup.py --env-only
docker compose up --build -d
docker compose exec api python -m app.seed
```

Интерфейс: [http://127.0.0.1:8080](http://127.0.0.1:8080). API: порт 8000. Контейнер API применяет миграции перед запуском; БД сохраняется в отдельном томе. Значения `semester_local` предназначены для локальной учебной среды.

```bash
docker compose down
```

Остановка без `-v` сохраняет том с данными. Конфигурация Compose подготовлена; в текущем окружении контейнерный запуск не проверен из-за отсутствия доступа к Docker daemon. Локальный запуск проверен на PostgreSQL.

## Работа в фоне и ссылка для преподавателя

На этом компьютере настроен отдельный запуск через пользовательские службы systemd: PostgreSQL, собранный React-клиент вместе с API на порту 8080 и внешний HTTPS-туннель. Он продолжает работать после закрытия терминала и чата. Автоматического отключения нет.

```bash
npm run demo:status
npm run demo:stop
npm run demo:start
```

Текущая внешняя ссылка выводится командой `demo:status` и сохраняется в `.local/hosting/url.txt`. Демо-аккаунт тот же: `demo@semester.app` / `Semester2026!`. После перезапуска самого туннеля адрес может измениться. Компьютер должен оставаться включённым, с доступом в интернет, без перехода в сон.

Подробности установки, журналы и ограничения — в [инструкции фонового запуска](docs/live-demo.md). Не запускайте одновременно локальные команды `dev:db` или Compose: они используют ту же БД либо те же порты.

## Миграции

```bash
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head
backend/.venv/bin/alembic -c backend/alembic.ini current
backend/.venv/bin/alembic -c backend/alembic.ini check
```

Схема создаётся только миграциями: `Base.metadata.create_all()` в приложении не используется. Откат `downgrade base` удаляет таблицы; он проверяется тестом исключительно в отдельной тестовой БД.

## Проверка

При работающей локальной БД:

```bash
npm run typecheck
npm run build
backend/.venv/bin/pytest -c backend/pytest.ini backend/tests
```

Тесты используют `TEST_DATABASE_URL` из `backend/.env` или окружения и отказываются работать с БД без окончания `_test`. Во время тестов очищаются только таблицы этой отдельной БД. Проверяются CRUD, JWT, хеширование, валидация, изоляция аккаунтов, фильтры, поиск и миграции. Тесты режима демонстрации требуют предварительного `npm run build`: они проверяют выдачу собранного интерфейса и прямое открытие его маршрутов. Результаты и браузерные сценарии описаны в [отчёте проверки](docs/verification.md).

## Структура

```text
backend/app/
  core/       настройки, сессия БД, JWT и общие зависимости
  auth/       аккаунт, вход, регистрация и профиль
  subjects/   модели, схемы, маршруты и правила дисциплин
  tasks/      модели, схемы, маршруты и правила заданий
  seed.py     необязательные демонстрационные данные
backend/alembic/versions/   версии схемы БД
backend/tests/              серверные интеграционные тесты
frontend/src/
  app/        маршруты, Redux store и общий макет
  features/   auth, dashboard, subjects, tasks, profile
  shared/     единый API-слой, типы, даты и общие компоненты
docs/         требования, пояснительная записка и сценарий защиты
```

Предметная модель: `users 1 → N subjects 1 → N tasks`. Доступ к заданию определяется через владельца его дисциплины. Дисциплина с заданиями не удаляется: сначала нужно удалить задания или перенести их через редактирование.

В `localStorage` сохраняется только JWT. Дисциплины, задания и профиль читаются и изменяются через API. Сервер проверяет JWT при каждом защищённом запросе. При 401 клиент завершает сессию и очищает кэш RTK Query.
