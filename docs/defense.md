# Демонстрация и подготовка к защите

## Сценарий на 3–5 минут

1. **0:00–0:40. Регистрация.** Открыть приложение, создать новый аккаунт. Показать пустой личный план. Объяснить, что данные разных пользователей разделены.
2. **0:40–1:20. Дисциплина.** Создать «Базы данных», указать преподавателя, цвет и описание. Открыть карточку, изменить описание.
3. **1:20–2:20. Задание.** Из карточки дисциплины добавить задание, указать дедлайн и высокий приоритет. Показать связь с дисциплиной. Изменить статус на «В работе», затем отметить выполненным.
4. **2:20–3:00. Поиск.** В списке найти задание по части названия, выбрать дисциплину и статус. Сбросить фильтры. Обновить страницу: данные сохранятся.
5. **3:00–3:40. Обзор и удаление.** Показать прогресс. Удалить созданное задание и затем дисциплину. Объяснить, почему дисциплина с заданиями не удаляется.
6. **3:40–4:30. Сервер и выход.** Показать Swagger и результат тестов. Выйти. При открытии защищённого адреса приложение направит на вход.

Для короткого показа можно войти в демо-аккаунт из README, однако регистрацию нужно уметь продемонстрировать отдельно. Не показывать содержимое реального `.env` и JWT-ключ.

## Что нужно понимать в коде

**Почему три сущности?** Пользователь владеет дисциплинами, каждая дисциплина содержит задания. Связи реализованы внешними ключами. В карточке задания виден предмет; в карточке предмета видны его задания.

**Где находится проверка прав?** На сервере. `current_user` проверяет подпись и срок JWT. Дисциплина выбирается одновременно по ID и `user_id`. Запрос к заданию соединяет таблицу дисциплин и проверяет владельца. При переносе проверяется и новая дисциплина.

**Зачем JWT, если есть защищённый маршрут React?** Клиентский маршрут отвечает за удобство. Запрос можно отправить напрямую, поэтому сервер обязан самостоятельно отклонять запрос без подходящего токена.

**Где хранятся данные?** В PostgreSQL. Redux содержит кэш и состояние интерфейса; `localStorage` содержит только токен. После изменения RTK Query сбрасывает соответствующие теги и загружает актуальные данные.

**Что хранится вместо пароля?** Хеш Argon2id с солью и параметрами. При входе библиотека проверяет пароль по хешу. Хеш не возвращается в профиле и не попадает в JWT.

**Зачем миграции?** Они фиксируют версии схемы. `upgrade head` создаёт таблицы, индексы и ограничения одинаково в новом окружении. Изменения схемы нельзя заменять ручными командами на единственном компьютере.

**Зачем две проверки формы?** Клиент сразу показывает ошибку, сервер защищает данные при прямом запросе или изменённом клиенте.

**Почему при чужом ID ответ 404?** С точки зрения аккаунта эта запись недоступна. Ответ не раскрывает существование чужих записей.

**Что происходит при истечении токена?** API возвращает 401, клиент очищает сессию и кэш, затем показывает вход с сообщением. Выход очищает токен на клиенте. Немедленного отзыва скопированного токена на сервере в текущей версии нет; он действует до `exp`.

**Какие ограничения у проекта?** Один личный учебный план на аккаунт, без совместной работы, вложений и уведомлений. Список заданий не разбит на страницы. Для большой нагрузки потребуются пагинация и дополнительные индексы. Для публичного размещения потребуются HTTPS, отдельные настройки секретов и ограничение частоты попыток входа.
