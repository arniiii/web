# HTTP API

Базовый адрес локально: `http://127.0.0.1:8000/api`. Формат запросов и ответов — JSON. Полная схема доступна в `/openapi.json`, интерактивная документация — в `/docs`.

## Аккаунт

| Метод | Путь | Назначение | Авторизация |
| --- | --- | --- | --- |
| POST | `/auth/register` | Регистрация; 201, JWT и профиль | Не нужна |
| POST | `/auth/login` | Вход; 200, JWT и профиль | Не нужна |
| GET | `/auth/me` | Текущий профиль | Bearer |
| PUT | `/auth/me` | Изменение имени, вуза и группы | Bearer |

Регистрация: `{"name":"Студент","email":"student@example.com","password":"StrongPass2026!"}`.
Вход: `{"email":"student@example.com","password":"StrongPass2026!"}`.
Результат: `{"access_token":"...","token_type":"bearer","user":{...}}`.
Защищённые запросы передают `Authorization: Bearer <access_token>`.

## Дисциплины

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/subjects?search=...` | Личный список с поиском по названию |
| POST | `/subjects` | Создание; 201 |
| GET | `/subjects/{id}` | Одна дисциплина |
| PUT | `/subjects/{id}` | Полная замена редактируемых полей |
| DELETE | `/subjects/{id}` | Удаление пустой дисциплины; 204 |

Все маршруты защищены. Пример тела: `{"title":"Базы данных","teacher":"Преподаватель","color":"#8575b1","description":"SQL и проектирование"}`.
Ответ дополнительно содержит `id`, `created_at`, `task_count`, `completed_count`. Название уникально в пределах аккаунта. При наличии заданий удаление возвращает 409; автоматического удаления заданий нет.

## Задания

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/tasks` | Личный список с поиском и фильтрами |
| POST | `/tasks` | Создание; 201 |
| GET | `/tasks/{id}` | Одна запись с названием и цветом дисциплины |
| PUT | `/tasks/{id}` | Замена полей, включая перенос между своими дисциплинами |
| PATCH | `/tasks/{id}/status` | Изменение статуса |
| DELETE | `/tasks/{id}` | Удаление; 204 |

Пример тела: `{"title":"Лабораторная работа","description":"Подготовить решение","subject_id":1,"due_date":"2026-12-15","status":"todo","priority":"high"}`.
Статусы: `todo`, `in_progress`, `done`. Приоритеты: `low`, `medium`, `high`.
Для смены статуса достаточно `{"status":"done"}`.

Фильтры можно сочетать: `search`, `subject_id`, `status`, `priority`, `due_before`, `due_after`, `pending=true`. Границы дат включительные. `pending=true` исключает выполненные задания. Сортировка `sort=due_date|priority|created_at`; по умолчанию дедлайн по возрастанию, затем ID. Поиск не зависит от регистра, символы `%` и `_` рассматриваются как обычные символы.

## Ошибки

| Код | Ситуация |
| --- | --- |
| 401 | Нет JWT; токен повреждён, просрочен или подписан другим ключом; неверные данные входа |
| 404 | Запись отсутствует либо принадлежит другому пользователю |
| 409 | Повторный email, повторное название дисциплины, удаление непустой дисциплины |
| 422 | Не заполнены поля, неверный формат, неизвестный статус или лишнее поле |

Ошибки содержат понятное сообщение в `detail`. Ошибка валидации также содержит список `fields` без исходных значений запроса. Пароли и их хеши отсутствуют в схемах ответов. Попытка присвоить `user_id` через JSON отклоняется; владелец берётся из JWT.
