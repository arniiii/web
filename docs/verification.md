# Проверка проекта

Дата: 5 ноября 2026 года. Окружение: Linux, Node.js 24.21.0, Python 3.12.3, отдельный локальный PostgreSQL.

## Автоматические проверки

| Проверка | Результат |
| --- | --- |
| `npm run build` | TypeScript и production-сборка Vite прошли |
| `pytest -c backend/pytest.ini backend/tests` | 31 тест прошёл |
| `alembic -c backend/alembic.ini upgrade head` | Миграция применена к основной локальной БД |
| `alembic -c backend/alembic.ini check` | Расхождений моделей и схемы нет |
| `docker compose config --quiet` | Конфигурация корректна |
| HTTP `/api/health` и интерфейс | Ответ 200 |

Серверные тесты работают с отдельной БД `semester_test`, созданной тем же PostgreSQL. Среди проверок: регистрация и вход; профиль; уникальность email; Argon2id; отсутствие или повреждение JWT; истечение токена; неподходящие ключ и алгоритм; недопустимый пользователь; полный CRUD; отказ в доступе к чужим данным; запрещённый перенос задания в чужую дисциплину; валидация и лишние поля; поиск, включая кириллицу и буквальный `%`; комбинированные фильтры; сортировка; откат и применение миграции с проверкой схемы.

При запуске тестов зависимость Starlette выводит предупреждение об устаревшей интеграции с `httpx`. Оно не влияет на результат; при обновлении тестового стека потребуется перейти на рекомендованный Starlette клиент. Ошибок тестирования нет.

До остановки процессов через HTTP считаны 4 дисциплины и 9 заданий демо-пользователя. Затем API и PostgreSQL остановлены и запущены повторно с тем же каталогом данных. Повторное чтение вернуло те же записи; сравнивались все поля JSON, а не только количество.

## Проверка через браузер

- Вход в демо-аккаунт и загрузка его учебного плана.
- Проверка формы новой дисциплины без обязательного названия; корректное создание дисциплины.
- Создание задания из карточки дисциплины с автоматической привязкой.
- Редактирование названия, дедлайна и статуса; сохранение новой даты 20 ноября в карточке.
- Отметка задания как выполненного.
- Поиск по кириллице в другом регистре вместе с фильтром выполненных заданий.
- Выход; регистрация отдельного аккаунта с пустым планом без данных демо-пользователя.
- Редактирование учебной группы и сообщение об успешном сохранении.
- Проверка мобильной навигации и интерфейса при ширине около 600 px; обзор также проверен на широком экране около 1265 px.

Тестовые дисциплина и задание после сценария удалены через API. Публичный демо-план снова содержит 4 дисциплины и 9 заданий. Скриншоты находятся в `screenshots/`.

## Дополнение 6 ноября 2026 года — фоновая демонстрация

Добавлен режим выдачи собранного React-клиента вместе с API на одном адресе. Полный набор теперь содержит **40 успешно пройденных тестов**: дополнительно проверены прямые маршруты React, корректные 404 для отсутствующих API и файлов, а также сохранение JWT-защиты.

Управление и ограничения доступности описаны в `live-demo.md`. Актуальный адрес хранится в игнорируемом файле `.local/hosting/url.txt`.

## Дополнение 6 ноября 2026 года — загрузка интерфейса

После сообщения о белом экране проверены внешний адрес регистрации, загрузка CSS и JavaScript, вход и отображение учебного плана. Ошибка в проверочном браузере не повторилась; причина на устройстве пользователя пока не установлена.

В начальный HTML добавлен независимый от React экран загрузки. При ошибке основного скрипта или ожидании дольше 15 секунд он показывает сообщение и ссылку обновления. Ошибки отображения React обрабатываются общей границей ошибок. Для HTML отключено кэширование, включая условные ответы 304; целевой синтаксис сборки понижен до ES2018.

Пройдены сборка с проверкой TypeScript и 12 серверных проверок режима демонстрации. Отдельно проверены обработчики ошибки скрипта, таймаута и успешного запуска. Экран отказа при недоступном основном скрипте проверен в браузере; проверка медленного соединения в браузере не завершена.
